# 外部 Codex / Claude Code 转谱与网站导入

当前约定为 `shengjian.score` v1。外部工具最终必须交付 UTF-8 文件 **score.shengjian.score.json**；HTML、图片预览、MIDI、MusicXML 或一段生成代码均不能替代这个 JSON。格式合规通过网站校验，音高、节奏和歌词仍需对照原图审阅。

## 操作顺序

1. 点击网站「添加歌曲」。创建窗口即可复制通用外部转谱提示词。
2. 创建后在「素材」上传谱图和音频。这里也有复制按钮：此时复制的提示词会包含当前谱图来源清单；也可直接进入「导入外部转谱 JSON」。
3. 把提示词、原始谱图以及可选人工歌词交给外部 Codex / Claude Code。网站复制按钮不会发送任何素材或调用模型。
4. 要求工具实际保存 score.shengjian.score.json，并自行解析、校验 Schema、引用和精确分数。需要预览时可以另外交付，导入仍使用 JSON。
5. 打开本曲「识谱 → 外部转谱导入」，选 JSON 文件或粘贴完整 JSON，不要包含 Markdown 围栏。按需把逻辑来源关联到本曲上传的谱图。
6. 点击「校验并创建审核草稿」，对照原图查看音符、歌词、节奏提醒和重叠候选，明确确认后应用。导入本身不改歌曲；标题、歌手等资料不会被外部结果覆盖。歌曲版本变化时会阻止覆盖人工纠错。

## 必需的数据结构

下载即可使用的文件：[完整示例](formats/shengjian-score-v1.example.json)、[完整JSON Schema](formats/shengjian-score-v1.schema.json)、[完整复制提示词](formats/external-transcription-prompt.zh-CN.txt)。网站使用同一套约定；本曲提示词额外包含当前图片清单。

| 字段 | 外部工具应当输出 |
| --- | --- |
| format / version | 固定为 `shengjian.score` / `1` |
| metadata | 全局 key、四分音符单位 bpm、timeSignature数组，例如 `[4,4]`；读不清用null |
| sources | 逻辑来源ID与图片名，不能是待访问的URL或执行命令 |
| phrases | 乐句ID与标签，音符用phraseId引用；可跨小节 |
| measures | 按原页、谱行、小节顺序的数组，各小节包含sourceId和notes |
| notes[].degree | 1–7音级；0休止；null未知且uncertain=true |
| notes[].octave | 相对无点do的八度，上方一点+1、下方一点-1；不猜演唱者音区 |
| notes[].duration | 正分数 `[分子,分母]`，单位是四分音符拍，例如八分音符`[1,2]`，不是秒 |
| notes[].lyric / phraseId | 该音对应字词与已有乐句ID；双行写为 `"第一行\n第二行"`，两行分别对齐到同一音；两行都无新词时为空字符串 |
| notes[].rhythm | 可选的下划线、附点、延长线、连音组证据；必须与duration精确相同 |
| warnings / provenance | 具体疑点、缺失范围、重叠证据，以及如实记录的工具与检查方法 |

同类ID唯一，限1–80位ASCII字母、数字、点、下划线、连字符，引用必须存在。整个包最多2MB/20000音符；单音歌词最多1000UTF-8字节。不清楚时不能用任意音符补齐，不能把未知改成休止；若只能完成部分内容，应明确列出未完成范围。

节奏、延音线、连音弧和拍号异常的完整语义见[格式与设计](08-recognition-and-external-import.md)。目前限单声部线性主旋律及全局调号、拍号、速度；复杂反复、多声部、中途变化不能无损表达时必须警告。

## 双行歌词：两遍、翻译或空耳

沿用 **shengjian.score v1**，不增加新字段。`lyric` 仍是字符串，用一个 LF 换行分隔上下两行。在 JSON 文件里写转义的 `\n`；JSON 解析后应得到真实换行。不能写成 `\\n`、`<br>`、`/` 或 `|`，不能输出 `lyric2` 或 `lyrics` 数组。

| 用途 | 单个音符的 JSON 字段 | 上行 / 下行 |
| --- | --- | --- |
| 两遍不同的歌词 | `"lyric": "清\n微"` | 第一遍“清” / 第二遍“微” |
| 原词和翻译 | `"lyric": "Hello\n你好"` | 原词 / 翻译 |
| 原词和空耳 | `"lyric": "Hello\n哈喽"` | 原词 / 空耳 |
| 只有上行有新词 | `"lyric": "清"` | 上行“清” / 下行空 |
| 只有下行有新词 | `"lyric": "\n微"` | 上行空 / 下行“微” |
| 两行都无新词 | `"lyric": ""` | 两行空；例如拖腔续音 |

两行按音符挂接，不要求字数、语言或词长相同。例如原词“清风”对译“Gentle breeze”，三个音可以分别写：

```json
[
  {"lyric": "清\nGentle "},
  {"lyric": "风"},
  {"lyric": "\nbreeze"}
]
```

以上只是三个 `lyric` 字段的片段演示，**不能作为完整转谱包导入**；完整字段见可下载示例。译句也可以整体挂在对应短语首音，不必硬拆成与原文等量的字；后续音的该行留空。英文单词间需要的空格应保留。每一行独立处理拖腔，不能因为上行空就删除下行；休止不挂新词，`tieFrom` 延音续片的两行都必须为空。

可选地在已有的 `provenance` 里说明两行角色：

```json
{
  "lyricRows": {
    "first": "第一遍歌词",
    "second": "第二遍歌词",
    "kind": "alternateVerse"
  }
}
```

这个片段放入根对象的 `provenance`，不是增加根字段。`kind` 的说明值可为 `alternateVerse`（两遍）、`translation`（翻译）、`phonetic`（空耳）、`unspecified`（不确定）；标签可自行填写。角色信息仅作为来源说明保留，网站不会据此自动切换播放遍数。

- **两行只是同一旋律的并排文字**，不增加音符、不改变音高或时值、不自动展开第二遍。如果两遍旋律/时值不同，或需要真正播放完整反复，应分别记录对应的实际音符段并注明原谱结构。
- 保留图上或用户提供的第二行。缺失翻译/空耳时，不自行补写；用户明确要求生成时，可另行补充，但要在 `warnings` / `provenance` 标明生成来源。关系看不清就保留上下顺序并说明疑点。
- 两行合计（包括换行）仍最多 **1000 UTF-8字节**，整个包最多2MB；不是每行各1000字节。新输出使用一或两行；已有单行工程继续兼容。
- 网站的草稿审阅、简谱、歌词视图与五线谱可显示两行；音符编辑有独立的第一行、第二行输入。歌词下载按乐句逐行拼接，网页MusicXML下载使用编号歌词行；工程JSON完整保留换行。
- 服务端基础Schema已经允许字符串中的LF，无需升级版本。网站示例和离线示例通过同一个共享函数补充双行；直接调用旧服务端 `/api/songs/:id/export/musicxml` 时，仍会得到原有的单个text内换行形式，网页下载会转换为编号行。

## 新增样例与素材格式

本轮只读发现 `原色/page1.avif、page2.avif`、`starfall/page1.png–page3.png`、`moon halo 简谱.jpg`。这些是输入素材，不是结构化谱面，不会自动调用模型转谱。AVIF素材由浏览器解码后以PNG上传，原目录文件不改动；转换失败时提供明确提示。PNG/JPG/WebP保持既有上传方式。

模型识谱改进已按用户要求暂停并存档，见[当前交接](07-handoff.md)；不要因发现新样例而自行恢复模型实验。
