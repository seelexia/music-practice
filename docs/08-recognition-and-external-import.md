# 识谱工作流与外部转谱 v4

2026-10-29。使用入口：打开歌曲 →「识谱」→「外部转谱导入」。同页保留内置视觉模型、人工歌词校对、草稿审阅。实际验收状态见 [交接](07-handoff.md)，识别准确度见 [独立评估](recognition-evaluation.md)。

## 外部 Codex / Claude / 人工转谱

1. 在素材页上传谱图并确认顺序。也可以在没有上传图片时先导入包，之后自行关联。
2. 点击「复制本曲转谱提示词」，自行将原图和提示词提供给所选外部工具。网站不会向外部工具上传图片。浏览器拒绝自动复制时，会显示并选中完整提示词供手动复制。
3. 外部工具输出 `shengjian.score` v1 JSON 文件。点「下载格式规范」「下载示例模板」可查看完整约定；粘贴 JSON 或选择文件，不要粘贴代码围栏。
4. 可选择每个逻辑来源对应的本曲谱图。明确选择不关联时保持不关联；不通过文件名猜测关联、不访问包里的路径或网址。
5. 点击「校验并创建审核草稿」。结构、引用和节奏证据矛盾会显示具体 JSON 路径；小节拍数与拍号不符则保留实际时值并提醒。
6. 对照原图审阅简谱、音符差异、警告、重叠候选，再明确应用。应用受歌曲版本保护，更新谱面和历史，不替换标题、作者等歌曲资料。原始转谱包和来源映射保留在任务中，可下载。

原有音符编辑里的「导入草稿」继续支持内部 Score / 工程 JSON；它与外部转谱包是两个明确入口。

## 格式要点

规范和示例由 `src/score_package.rs` 生成，网站/API 与运行时共用，不维护另一份容易漂移的静态 Schema。

供离线工具阅读的生成快照：[JSON Schema](formats/shengjian-score-v1.schema.json)、[示例包](formats/shengjian-score-v1.example.json)、[通用外部转谱提示词](formats/external-transcription-prompt.zh-CN.txt)。网站复制按钮还会附加本曲当前图片清单。快照通过 `node tools/export_score_format.mjs` 从本机权威接口生成，修改协议后一起重新生成。

- `metadata`：全局 `key`、四分音符单位的 `bpm`、`timeSignature`。读不清用 null，临时继承当前工程并警告。`title` 仅保留在来源包中。
- `sources`：逻辑 ID 与显示名称；`sourceMapping` 在导入请求中另行给出本曲素材 UUID。来源名是文本，不是下载位置或可执行命令。
- `phrases`：稳定 ID 和实际乐句标签。音符 `phraseId` 引用它；一行可多句，一句可跨小节。
- 双行歌词仍用既有 `lyric` 字符串：`"第一行\n第二行"`，支持两遍不同词、翻译或空耳；每行独立按音挂接，只有下行时保留开头LF，两行空才写空串。合计仍限1000 UTF-8字节，不增加音符或自动播放反复。可在惰性 `provenance.lyricRows` 备注角色。详细片段、空行和来源规则见[使用说明](09-external-transcription.md)。网站提示词/示例的双行补充由web/external-prompt.ts共用，生成脚本也使用它；基础Schema和服务端编译器无需改动。
- `measures`：按原始页序、谱行和小节顺序记录，保留重叠。小节含 ID、sourceId、可选 row/pickup/annotations 和 notes。
- 音符：`degree` 为1..7，0为休止，null为未知且必须 uncertain=true；`octave` 是相对无点 do 的八度，`accidental` 为临时升降半音数。无点 do 的绝对音区沿用应用约定，可在练习时调整。
- `duration=[分子,分母]`，单位是四分音符拍。例如八分音符 `[1,2]`，附点八分 `[3,4]`。单音允许1/128..256拍。分数经约分精确比较，不靠浮点容差修正节奏。
- 可选 `rhythm` 证据：underlines/dots/extensions 缺省0；tuplet=[实际音数,通常音数]。计算：`2^-underlines × (2^(dots+1)-1)/2^dots × normal/actual + extensions`。不得与显式 duration 矛盾；显式 null 符号不能代替缺省值。
- 延长线属于前音，不能伪造新攻击。连音弧仅作为 annotations；同音延音线的后片段用 tieFrom 指紧邻前片段 ID，要求同音高、同乐句、空歌词。宿主合并发声，保留片段、分数和证据，印刷小节仍各记自己的片段时值。
- 未知音在预览中显示 `?` 并暂静音，不能当印刷休止。非普通二进制节奏以明确拍数标签显示；当前不宣称完整复刻所有连音符雕版。
- 最多2MB、20000音符、4000乐句、10000小节。ID限1..80位 ASCII 字母、数字、点、下划线和连字符，同类唯一、引用有效。未知字段拒绝，annotations/provenance 是惰性数据。

目前仅支持单声部线性主旋律及全局调号、拍号、速度。复杂多声部、中途转调/变拍/变速、反复与跳房子的无损表达尚未实现，外部提示词要求显式报告这些边界。

## 内置识谱 agent 与 harness

宿主负责素材清单、图像读取、精确节奏、校验、版本和任务账本。模型只能返回受限 JSON 工具动作，不能执行命令、任意读文件、联网、修改服务或访问评估器。

流程是完整页查看 → 模型按实际布局选择局部裁片 → 逐小节提交看到的符号 → 宿主计算节奏并检查 → 返回疑点和原始裁片复核 → 保存审核草稿。不存在歌曲名称、固定坐标、固定行数、目标总时长或歌词匹配的生产规则。默认路径不再使用旧版行投影阈值。

`inspect_page` / `inspect_crop` 提供图像；`submit_symbols` 只接受观察符号，拒绝模型直接给 duration/beat/midi；`set_metadata` 记录印刷全局信息；宿主 `validate` 的成功结果必须在后续请求可见，再 `review` 复看原图，最后 `finish` 显式声明每页覆盖情况。手动歌词是独立惰性数据，只能用于歌词和断句，不得覆盖印刷音高/节奏。

有固定请求数、动作数、裁片数、输出字节、上下文、预算和总运行时间上限。预算到达、非法工具、截断响应或结构失败会保存可追溯的部分材料和失败状态。任务记录含工作流版本、原图/发送图哈希、裁片坐标、工具动作、宿主检查、来源包和原始模型响应。预算计数是宿主预留上界，不代表供应商计费 token。

v1.3 的上限为64次模型请求、256个动作、96次裁片、12次可恢复协议错误、100万预留 token、2400秒总运行时间。上下文包含已查看区域、各区域已提交小节和当前图像焦点，图像在跨工具请求时保持可见。相同区域换名重复裁片会拒绝；新符号包先经过完整编译才替换旧观察，拒绝不合法延音线等结构错误时保留此前有效符号。仍不根据参考答案修正音高或时值。

请求使用 `response_format: {type:"json_object"}` 约束 JSON 语法，随后仍由宿主检查完整工具结构和音乐语义。这依赖配置提供商支持该接口；不支持时任务保留明确失败记录。能力说明见 [vLLM structured outputs](https://docs.vllm.ai/en/latest/features/structured_outputs/)。

覆盖完整是模型声明，结构合法是程序属性；两者都不能证明转录正确。部分完成和失败不能伪装为完整识谱；始终需要对照原图的人类审核。

## 评估隔离与可维护性

用户提供的 ground truth 只交给离线 `tools/evaluation/`。运行服务不读取该 HTML，模型工作线程也不接触参考答案。固定评估器先用合成夹具测试并冻结，再比较历史稿和新稿。指标分别报告漏音/多音、音高与八度、时值、歌词和小节覆盖，不能用 JSON 合法率或总时长代替准确度。

原始图像、音频、参考 HTML 和用户已应用的纠错保持只读。实验新稿不自动应用。一个歌曲参考集不能证明跨字体、布局或歌曲的泛化能力；合成机制测试与真实视觉准确度必须分别报告。

选择小型显式工具流程的依据及注意点见 [Anthropic agent patterns](https://www.anthropic.com/research/building-effective-agents)；结构规范使用 [JSON Schema2020-12](https://json-schema.org/draft/2020-12)。没有为本任务引入可执行任意代码的 agent SDK。
